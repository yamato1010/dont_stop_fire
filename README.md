# 炎を絶やすな（仮）

Unityで開発する、横スクロール2Dアクションゲームです。  
プレイヤーには寿命があり、時間経過や状況によって死に近づきます。  
しかし、死は単なる失敗ではなく、死亡時に残る“何か”を利用することで、次の挑戦を有利に進められます。

## コンセプト
**無駄な命はない。**

- 自動スクロールで進行する
- プレイヤーには寿命がある
- 死亡時、その場に“何か”が残る
- 残されたものやギミックを使って寿命を延ばし、ゴールを目指す

## ジャンル
横スクロール2Dアクション

## コアゲームループ
1. プレイヤーは自動スクロールの中で前進する
2. 寿命が減少していく
3. 障害物やミスで死亡する
4. 死亡地点に“何か”が残る
5. 次の挑戦でそれを使い、より先へ進む
6. 寿命を管理しながらステージを走破する

## 現時点の開発目標
### 短期目標
- コア1周が成立する最小プロトタイプを作る
- 1面のグレーボックスを最後まで遊べるようにする

### 中期目標
- 1stageを遊べる段階にする
- 1面のプレイ時間を5〜15分程度に調整する

### 長期目標
- 全体2〜3時間程度のゲームとして完成させる

## 開発環境
- Engine: Unity
- Version Control: Git / GitHub
- Language: C#
- AI Support: Codex

## ブランチ運用
- `main`: 常に動く状態を保つ
- `feature/...`: 機能追加
- `fix/...`: 修正
- `docs/...`: ドキュメント更新

ルール:
- main へ直接 push しない
- Pull Request 経由でマージする
- 1PR = 1目的
- 小さくレビューしやすい単位で出す
- Scene は同時に編集しない

## Codex の使い方
Codex は以下の用途で使います。

### 向いている用途
- 単体スクリプト作成
- バグ修正
- リファクタリング
- PR レビュー補助
- テスト用コード作成
- ドキュメント整備

### 向いていない用途

- 難易度調整の最終判断

- 企画意図の最終決定

## セットアップ
1. リポジトリを clone
2. Unity Hub で `UnityProject/` を開く
3. 必要な Unity バージョンを揃える
4. 初回起動後、動作確認を行う
5. 作業前に最新の `main` を pull する
6. 新しい作業ブランチを切る

## 開発ルール
- シリアライズ済みの Inspector 値を壊さない
- 不必要な asset rename をしない
- 共通仕様を変えるときは docs も更新する
- 動作確認手順を PR に書く
- コンソールエラーを放置しない
